## 1. 目的

本書は、TaskFlowの機能要件・非機能要件を定義し、設計・開発・テストの基準とすることを目的とする。

## 2. 用語定義

| 用語 | 定義 |
| --- | --- |
| タスク | 実施すべき作業単位 |
| プロジェクト | タスクを束ねる管理単位 |
| ワークスペース | 契約単位（組織）の管理領域 |

## 3. ステークホルダー

| 役割 | 責任 |
| --- | --- |
| プロダクトオーナー | 要件の最終承認 |
| 開発チーム | 実装 |
| QAチーム | テスト |
| エンドユーザー（PM/メンバー） | 利用・フィードバック |

## 4. スコープ

### 4.1 対象範囲

- ユーザー/ワークスペース管理
- プロジェクト管理
- タスク管理（作成/割当/進捗/コメント/添付ファイル）
- 通知機能（メール/アプリ内）
- レポート・ダッシュボード
- 課金・プラン管理

### 4.2 対象外範囲

- モバイルネイティブアプリ（次フェーズ）
- 外部会計システム連携（次フェーズ）

## 6. 非機能要件

| 分類 | 要件 |
| --- | --- |
| 性能 | 主要画面の表示は2秒以内（95パーセンタイル） |
| 可用性 | SLA 99.9%（月間） |
| セキュリティ | 通信のTLS化、パスワードハッシュ化、OWASP Top10対応 |
| 拡張性 | 同時利用ユーザー数[X]名までスケール可能 |
| 保守性 | CI/CDによる自動テスト・自動デプロイ |
| ログ・監査 | 操作ログの90日保持 |
| バックアップ | DBの日次バックアップ、[30]日保持 |
| 対応環境 | Chrome/Edge/Safari最新2バージョン |

## 7. ユースケース（例）

### UC-01 タスクを作成する

| 項目 | 内容 |
| --- | --- |
| アクター | プロジェクトメンバー |
| 事前条件 | ログイン済み、プロジェクトに参加済み |
| 基本フロー | 1. プロジェクト画面を開く 2. 「新規タスク」を押下 3. タイトル・担当者・期限を入力 4. 保存 |
| 事後条件 | タスクが一覧に表示され、担当者に通知される |

## 8. データ要件（概要）

| エンティティ | 主な属性 |
| --- | --- |
| User | id, name, email, role |
| Workspace | id, name, plan |
| Project | id, workspace_id, name, status |
| Task | id, project_id, title, assignee_id, status, due_date |

## 9. 受け入れ基準

- [ ] 機能要件（Must）がすべて実装されている
- [ ] 非機能要件を満たすことを総合テストで確認済み
- [ ] 重大・重要バグが0件である
