## 1. 目的

システムが要件定義書・外部設計書を満たしていることを、開発チームから独立した観点で検証する。

## 2. テスト対象範囲

### 対象
- 全機能要件（F-001〜F-010）
- 非機能要件（性能、セキュリティ、可用性）

### 対象外
- 次フェーズ開発予定機能（モバイルアプリ等）

## 3. テスト種別

| 種別 | 目的 | 実施方法 |
| --- | --- | --- |
| 機能テスト | 要件定義書通りの動作確認 | 手動テスト + Playwright E2E |
| シナリオテスト | 実利用フローの一連動作確認 | Playwright E2E |
| 非機能テスト（性能） | 応答時間・負荷耐性確認 | 負荷試験ツール（[k6/JMeter等]） |
| セキュリティテスト | 脆弱性診断 | [外部診断ベンダー / OWASP ZAP等] |
| 回帰テスト | 修正による影響確認 | 既存E2Eスイートの再実行 |
| ユーザビリティテスト | 実際の利用感の確認 | 社内ユーザーによる試用 |

## 4. テスト環境

| 項目 | 内容 |
| --- | --- |
| 環境 | ステージング環境（本番同等構成） |

| ブラウザ | Chrome / Edge / Safari（最新2バージョン） |

## 7. Entry基準（テスト開始条件）

- [ ] 対象機能の実装が完了している
- [ ] 単体テスト・結合テストが完了している
- [ ] テスト環境が構築済み

## 8. Exit基準（テスト完了・出荷判定条件）

- [ ] 計画したテストケースの実施率100%
- [ ] 重大（Critical/Blocker）バグ 0件
- [ ] 重要（Major）バグの残存が[N]件以下、かつ回避策あり
- [ ] 非機能テストの目標値をすべて達成

## 9. 不具合管理

| 重大度 | 定義 | 対応期限目安 |
| --- | --- | --- |
| Critical | サービス停止・データ消失 | 即時対応 |
| Major | 主要機能が使えない | リリース前必須対応 |
| Minor | 軽微な表示崩れ等 | リリース後対応可 |
